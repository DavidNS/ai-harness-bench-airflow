Dags gain a transient ``draining`` scheduling state ("drain, then pause"): the Scheduler stops creating new runs while the runs already in flight finish, then pauses the Dag by itself. The REST API exposes it as ``scheduling_state`` (``active``, ``draining`` or ``paused``), accepted by ``PATCH /dags`` and ``PATCH /dags/{dag_id}`` as an alternative to ``is_paused``, which keeps working unchanged.
