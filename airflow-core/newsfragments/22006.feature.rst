Dags can now be drained: the new ``draining`` scheduling state stops new scheduled runs while the runs in progress finish, after which the Scheduler pauses the Dag by itself. Set it with the new ``scheduling_state`` field of ``PATCH /dags``; ``is_paused`` keeps working, and ``airflow dags pause``/``unpause`` end a drain. The Dag list in the UI API gains a ``scheduling_state`` filter and ``has_unfinished_runs``.
